# OpenRF v0.2.33 — Release tests and field limits

1. Stop the existing OpenRF server with Ctrl+C; leave local Docker Valhalla running. In Windows PowerShell run `powershell.exe -NoProfile -ExecutionPolicy Bypass -File 'C:\projects\OpenRF\Update-OpenRF.ps1'`, with the downloaded ZIP in Downloads. In Ubuntu restart with `cd /mnt/c/projects/OpenRF && python3 -m openrf`.
2. Open `http://127.0.0.1:8765/` in Firefox; Ctrl+Shift+R. The Survey Map should show only Destination, Choose destination on map, Get directions, and Start navigation over the map. A small gear next to the map credits opens online address/provider settings. Enable/disable online lookup there; preference persists in this browser. Typed addresses are sent to MapTiler/Photon/Census only when enabled. GPS positions are never sent to these providers.
3. Confirm local Valhalla real-road directions continue to work; the red destination pin can still be dragged. Select Start navigation only after a confirmed road route. Open GPS details under the compact status for reported accuracy and fix freshness.
4. Test a coarse desktop fix around ±107 m: the status should describe approximate accuracy and *pause* turn guidance, not say GPS is missing. The map may recenter broadly. Test precise position with compatible GPS hardware later. Keep turns and rerouting disabled when quality is inadequate. Stop navigation and confirm the geolocation watch is cancelled.
5. Without any GPS: verify an explicit browser permission/error status. Browser GPS on Windows/WSL is often based on Wi-Fi/IP and is not equivalent to a physical GNSS receiver. Do not navigate a vehicle by this beta feature.
6. Run `python3 -m unittest discover -s tests -q` and `node tests/test_map_navigation_v033.js` in Ubuntu. Actual Firefox rendering, optional provider keys, live Valhalla, sensor, and road tests require the user's machine.
