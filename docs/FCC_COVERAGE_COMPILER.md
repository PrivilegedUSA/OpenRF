# FCC H3 offline coverage compiler — v0.2.227

Local-only first implementation. Download the **By Geography** state ZIPs for 4G LTE, 5G NR, Mobile Voice, H3 shapefile, matching filing and release. The California filenames begin `bdc_06_4GLTE_`, `bdc_06_5GNR_`, and `bdc_06_MobileVoice_`. Keep original ZIP files in Downloads. Fixed broadband and summary ZIPs are ignored. No FCC account, network or upload is used by the compiler itself.

In Ubuntu WSL, install the optional compiler dependencies (PyShp MIT and pyproj MIT; PROJ MIT). They are not needed by the map runtime. Use Ubuntu's Python for the installed packages:

```bash
sudo apt update && sudo apt install -y python3-pyshp python3-pyproj
cd /mnt/c/projects/OpenRF
/usr/bin/python3 -m openrf.fcc_coverage scan --state 06
/usr/bin/python3 -m openrf.fcc_coverage build --state 06
```

If multiple Windows Downloads directories contain matching files, specify `--input-dir '/mnt/c/Users/YOUR_USER/Downloads'`. `scan` checks filenames, archive directory, DBF field names, source row counts and required component sizes, not every byte. `build` streams extraction of the relevant components with CRC checking, inspects CRS, fields and records, and shows measured row counts/percentages. All three datasets must have the same release/filing; the latest release for each selected state is used (choose `--release YYYY-MM-DD` to override). Omit `--state` to build all complete matching states; any incomplete selected release blocks the build before processing. Use an explicit `--db PATH` for a custom OpenRF main database. Do not run concurrent compiler processes on the same pack. Stop OpenRF while compiling if convenient; it only reads published packs.

The output is `~/.local/share/openrf/fcc-coverage/fcc-06.sqlite3` (or the equivalent directory beside your custom main DB). No source, observation, tower, camera or mesh data are removed. The compiler writes a temporary state pack and atomically replaces the previous pack only after all three sources finish and SQLite validation passes. Each geometry is canonicalized at seven decimal degrees and stored once per H3 ID and geometry, with compressed polygon rings, spatial R-tree, and separate carrier/provider/technology/environment membership. Source filenames, filing/release, row counts, original provider IDs and names are retained. Unknown carrier names are grouped as Other carriers for rendering; no guessing. 5G 7/1 and 35/3 are distinct, as are FCC environments 0 (outdoor stationary only) and 1 (both outdoor stationary and in-vehicle). Voice is separate. Outdoor stationary (all) is the union of codes 0 and 1, not an additional source claim; the UI defaults to the LTE union when available. Exact source geometries, not artificial tower circles; no inferred indoor coverage. State-level coverage may take substantial disk space and time, and the output size is not yet benchmarked on full California files. Keep several GB free (more may be required); compiler reports insufficient extraction space and stops on storage errors. Unsplit dateline polygons are rejected rather than drawn across the world; Alaska compatibility needs verification. No aggregate/coarse zoom tiles yet; large viewports are deliberately hidden at existing vertex limit. Zoom in to neighborhood level to verify each profile. A blank map is not a no-service claim.

After building, start OpenRF and select Map → Layers → Cellular infrastructure & coverage → Reload saved cellular data. Enable a carrier and select its coverage profile. Existing manually imported coverage packs remain independent. Data stays offline and outside source control. The CLI prints the state pack size and SHA-256. Full nationwide redistribution/hosting and one-click download are not implemented; verify redistribution permissions and benchmark real packs before publishing. No FCC dataset is shipped in source.
