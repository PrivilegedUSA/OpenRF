# Offline maps — v0.2.10 area manager

OpenRF's original raster fallback was requesting public OpenStreetMap raster tiles, which can produce a 403 block and **must not be used for bulk/offline-area downloads** under the OSM tile use policy (https://operations.osmfoundation.org/policies/tiles/). v0.2.9 removes that dependency entirely.

## What works without internet

- Browser GPS positioning, manual survey coordinate selection, saved observation pins, category filters, and interactive grid pan/zoom in **Offline / raster** mode.
- **Raster MBTiles** basemaps (`.mbtiles`) you independently obtain or generate with permission for offline use. Use **Manage offline map areas → Import selected file** to import one from your browser, or continue copying packages manually. The **Offline basemap** dropdown selects one and **Refresh maps** rescans the private folder. No network request occurs while serving locally installed tiles. Overzoom displays the nearest available package zoom; missing tiles leave the grid visible.
- SQLite investigations, exports, captures and sensor API; no automatic upload or local database migration.

**What does not work fully offline yet:** the standard online OpenFreeMap street/dark vector tiles, in-app generation/downloading of new geographic map packages, route navigation, full vector MBTiles/PMTiles, multi-zoom offline tiles generated by OpenRF, and automatic offline map style/glyph download. No basemap package is shipped. Never confuse a blank basemap with an observation/data loss.

## Manage offline map areas inside OpenRF (v0.2.10)

1. Obtain a licensed, **raster** `.mbtiles` file first. OpenRF does **not** fetch or construct map packages from public tile servers, and a map-provider API key alone does not grant download permission.
2. Start OpenRF, open **Survey Map → Manage offline map areas** (expand it), and choose the file from your Windows/WSL browser using **Import selected file**. Up to **1 GiB per file** is accepted in this initial release. Browser uploads stream through OpenRF's **local loopback** server in bounded chunks; they are not uploaded to external providers. Do not close the tab mid-import.
3. The importer validates a standard MBTiles SQLite structure, required raster metadata, sample tile signature, and zoom range. Invalid or incomplete imports are rejected without replacing existing map packages. Duplicate names require renaming the file or explicitly removing the older package first.
4. Choose your installed map from **Offline basemap**. Expand the area manager to review its declared bounding coordinates (if supplied), zoom range, size, image format, and attribution. **View area on map** centers the offline renderer on those bounds, but actual tile coverage may be smaller than the declared bounds. Survey pins remain observation locations, not transmitter locations.
5. **Remove selected map** asks for confirmation and deletes only that local `.mbtiles` file. It does not delete SQLite observations, captures, investigation sessions or cached firmware. If a map has no declared bounds, area zoom is unavailable, but selection remains functional.

**No map packages are included in the source ZIP**. This release does not support selecting an arbitrary square on the map and downloading it, and OpenStreetMap's public raster server must not be used to prefetch tiles. Imports and removals are local and explicit; all original source files on the user's computer remain unchanged.

## Manual installation (still supported)

1. Obtain a **prebuilt raster MBTiles** file from a provider that explicitly permits offline use, or generate one yourself from appropriately licensed sources. The `metadata` table must declare `format` as `png`, `jpg`, `jpeg` or `webp`, and the standard MBTiles `tiles` table must contain TMS tile rows. Vector `pbf` packages are intentionally unsupported. Attribution may be included in the metadata.
2. In your **Ubuntu WSL terminal**, create the private map directory:

   ```bash
   mkdir -p ~/.local/share/openrf/maps
   ```

3. Copy `my-area.mbtiles` into that directory. For example, replace `WINDOWS_USERNAME` with your Windows username:

   ```bash
   cp /mnt/c/Users/WINDOWS_USERNAME/Downloads/my-area.mbtiles ~/.local/share/openrf/maps/
   ```

   Filenames may contain ASCII letters, digits, `_`, `-` and `.`; they must begin with a letter or digit. Do not put files in `C:\projects\OpenRF`, Git, source ZIPs, or `project/`.
4. Start OpenRF and open **Map**. Press **Refresh maps**, select the package in **Offline basemap**. The app switches to local raster mode. If it is not listed, check whether it is a *raster* MBTiles with the required tables, a readable file, and proper filename.
5. To verify offline operation, disconnect internet **after loading the page** and confirm the basemap you selected, survey pins and observation placement still work. The built-in grid needs neither connectivity nor third-party JS.

For a nondefault `--db` path, place the `maps/` directory alongside that database. The local map API never allows the browser to request files outside this folder. A map's view extent and zoom levels depend on what the package actually contains; it cannot provide roads outside its coverage.

## Optional: cache MapLibre's JavaScript and CSS

When internet is available, run from your installed project directory:

```bash
python3 tools/cache-maplibre.py
```

This explicitly downloads the pinned MapLibre 5.24.0 JS and CSS library files to `~/.local/share/openrf/assets/`, outside Git and the source updater. When absent, OpenRF redirects the library requests to the same upstream CDN used in v0.2.8. With cached library assets, **OpenFreeMap vector street/dark styles still require live internet**. You can instead select the offline grid or local raster MBTiles. This optional helper was not run in an internet-connected environment during development; it needs testing on your WSL machine.

## Attribution and privacy

MapLibre (BSD-3-Clause) and OpenStreetMap-derived data have different licenses. OSM-derived map data typically requires ODbL attribution; an offline raster archive may have additional provider-specific rules. Do not assume any service's API key grants bulk download rights. Preserve a package's `attribution` metadata and confirm permissions. Locally supplied tiles, survey observations and location records are not automatically uploaded by OpenRF. Online basemap views still contact online map providers; use offline mode for field privacy.
