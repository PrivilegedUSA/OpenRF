# OpenRF 0.2.219 release verification

Baseline: complete OpenRF 0.2.218 source bundle. New changes are confined to the public mesh directory module, server routes, map controls, styles, traffic downloader/status, tests and version/release metadata. Existing caches and database tables are unchanged.

REPMAP source: https://repmap.arg0net.org/ and its documented read-only GET https://repmap.arg0net.org/data. Provider implementation and sample shape reviewed at https://github.com/argo79/Reticulum_Entry_Points_Map. Only explicit operator-coordinate or manually published public interface rows are accepted, not name, WHOIS or IP-derived estimates. Positions are rounded to three decimal places, not measurements of radio reach or verified device locations. Entries without eligible positions are omitted and counted. No credentials, connection hosts, private messages or routing history retained. The public directory is downloaded only by explicit user action. Separate JSON cache expires from display after seven days; refresh errors preserve the cache file. No provider dataset or upstream code bundled; redistribution terms for the provider's data have not been established.

Traffic retry: transient HTTP 408/429/500/502/503/504 and network connection or timeout failures are retried at most twice. Default wait 2 and 4 seconds; longer Retry-After honored up to 30 seconds, otherwise that source is deferred until the next manually requested refresh. Bad payloads and nontransient HTTP errors are not retried. Source caches remain independent. Provider warnings are separate from saved counts and terminal progress bars disappear.

Acceptance: manually download Reticulum, inspect source-labelled purple pins, toggle transport and all nodes separately, switch basemaps, restart and check cached map without network. Confirm the other two caches remain intact. Update US cameras and inspect retry/status behavior; a persistent provider failure is not a successful update. Provider host DNS unavailable in development environment: live REPMAP and Chicago downloads and rendered browser UI not verified. No physical hardware testing performed.
