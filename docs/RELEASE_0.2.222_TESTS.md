# OpenRF 0.2.222 — map marker and feature focus checks

Display-only changes: remove visible mesh pin borders and shadows; preserve bright network palette and anchored overlap badges. Single markers and one/two-digit count clusters share a 19-pixel footprint; larger counts can expand to fit text. The overlap badge remains wider. Keyboard focus indicators are retained. Snap to location actions use original reported coordinates, zoom to at least 17 (or the existing closer zoom), honor reduced-motion settings and suspend navigation camera following without ending navigation. They do not change GPS, route or stored coordinates. Public single-node details put the action at the top; cluster details expose it per listed node. Camera, local mesh, observation and vector survey waypoint/SDR popups also expose it. Raster SDR and waypoint markers were not interactive previously and are unchanged. No changes to cache formats, provider endpoints, schema or layer preferences.

Changed files: `openrf/static/{app.js,app.css,public-mesh.js,camera-layers.js,mesh-dashboard.js}`, `tests/test_map_feature_snap_v222.js`, `tests/test_public_mesh_overlap_v220.js`, release metadata, static cache keys, User-Agent versions, README and changelog.

Acceptance: enable all three mesh networks, verify smaller bright borderless pins and overlaps on each basemap. Open individual and mixed node details and snap to a chosen reported point. Test ALPR, speed and red-light points, local mesh and saved observations. While stationary in a navigation session, verify snap pauses camera follow and the normal GPS crosshair resumes it. Check both MapLibre and raster fallback. No database refresh is necessary.

Validation: JavaScript full suite (178 suites), source syntax checks, focused coordinate/overlap regressions, and isolated Chromium computed-style fixture (19 × 19 pixels for ordinary markers and two-digit clusters, zero border and no shadow; overlap 29 × 19 for two networks). Full interactive browser map, real providers and physical hardware were not exercised for this UI-only release.

Final validation: the first Python run found a stale weather script version header; corrected header and passed all 11 weather tests, then reran full Python discovery: 647 tests passed (84.443 seconds). The isolated Chromium popup DOM click test also passed (selected coordinates and requested zoom 17). Full JavaScript suite passed before the header-only correction; syntax check and the weather JavaScript test passed after it.
