# OpenRF v0.2.12 — Local raster tile ZIP conversion

This feature does **not download map tiles** or render them from raw OSM extracts. It converts a user-supplied, **appropriately licensed** ZIP of already-rendered raster tiles into a local offline MBTiles basemap. A provider's ordinary online map API key is not proof of bulk/offline download rights.

## Supported input

- ZIP entries: `2/0/1.png`, `tiles/2/0/1.png`, or `my-export/tiles/2/0/1.png`. JPEG and WebP work too, but use **one image format per ZIP**. Optional top-level `README.txt`, `LICENSE.txt`, `attribution.txt`, or `metadata.json` are accepted but not trusted. Tile paths are Web Mercator `z/x/y` with integer zoom 0–18; select **XYZ** (north-origin y) or **TMS** (south-origin y) as appropriate.
- Create/save an area in OpenRF first; the file is clipped to the saved area and requested zooms. If the ZIP contains a world basemap, OpenRF does *not* keep out-of-region tiles. If your archive has unrelated deeply nested directories or vector tiles, convert it with a properly licensed tool before importing.
- The output is a private `~/.local/share/openrf/maps/<name>.mbtiles` on default Ubuntu/WSL installations. The original ZIP remains unchanged on your computer. No map files go into the Git-managed source or release ZIP.
- Enter **required attribution and source name** in the UI. The source name is stored as metadata and attribution is shown on the map. Preserve any required license notices outside OpenRF as well. You—not the application—must verify the license permits offline storing and converting a ZIP to MBTiles.

## Step-by-step

1. Visit **Survey Map → Manage offline map areas**. Select or save a field region. Export **tile plan JSON** to see the bounds and XYZ tile ranges. The JSON is for planning and comparison only—it has no tile images or provider URL.
2. Obtain a permitted **raster XYZ/TMS tile archive** from an authorized provider, or produce one with your own local tile rendering process using suitable data and licenses. Do not bulk-download from OpenStreetMap's public tile servers (https://operations.osmfoundation.org/policies/tiles/) or assume that OpenFreeMap online styles are licensed for bulk harvesting.
3. In **Prepare a map from a licensed tile ZIP**, select `.zip`, choose a fresh output map name, type provider/source and attribution text, select XYZ or TMS coordinate scheme, confirm offline/derivative rights, then import.
4. OpenRF installs a new MBTiles package (if matching tiles exist) and selects it. Switch to **Offline / raster**, zoom around your area, inspect actual coverage and verify the data-provider credits in the map attribution disclosure. A successful import does **not** mean every area tile exists.
5. To remove a package, select it and use **Remove selected map**; doing so does not delete your saved area plan, survey points or investigations.

## Limitations and safety

The ZIP is sent to OpenRF's local loopback-only Python server, not to an external service. Upload size is capped at 512 MiB, expanded contents 512 MiB, entry count 15,000 and output 10,000 image tiles/512 MiB. ZIP entries aren't extracted; mixed images, unsafe paths, duplicates, invalid coordinates, corrupted data and existing target filenames are rejected. A successful conversion is not a licensing certification or a guarantee of geographic completeness.

The in-app importer currently supports **raster** images only. It cannot render `.osm.pbf` downloads into streets, display vector PMTiles, download a provider region, use an API key, or select a remote URL. Those are distinct future development tasks. GPS/observations stay separate and no RF data are generated by converting map tiles.

## Test fixture (not a real map)

Automated unit tests build tiny **SYNTHETIC TEST ONLY** PNG ZIP entries with `z/x/y.png` names, convert and read them through the normal local tile API, verify XYZ-to-TMS conversion and check failure/permission paths. They do not contact tile servers. See `tests/test_tile_archive.py`.
